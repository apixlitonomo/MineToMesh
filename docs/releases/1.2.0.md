# MineToMesh 1.2.0

MineToMesh 1.2.0 fixes black faces and flicker on exactly overlapping faces in ordinary block models, adds quad-preserving OpenUSD (USDA) export, and provides a locked selection preview that is isolated per world or server and persists across restarts.

## Changes

### Exact coplanar quad layering

- A stable geometry fingerprint is built for `BakedQuad`s within the same block whose coordinates are exactly identical, tolerating rotated vertex cycles and reversed ordering.
- The first layer stays in place, and later overlapping layers are offset incrementally by `1/1024` block along their own normals.
- All geometry such as Powered Rail and the grass block base layer plus tint Overlay is kept; Z-fighting is not avoided by deleting faces.
- Detection only applies to ordinary block models; the output of fluids, entities and block-entity renderers is unaffected.
- The `report.json` schema is raised to 3, adding aggregate `geometryAdjustments` statistics and degenerate-normal diagnostics.

### USDA / OpenUSD export

- Every export produces glTF, BIN, USDA, external PNG textures, material sidecar files and `report.json`.
- glTF continues to be triangulated as the specification requires; USDA keeps the source quads, and every mesh is fixed to `subdivisionScheme = "none"`.
- The USDA stage uses Y-Up, `metersPerUnit = 1`, external textures and UsdPreviewSurface materials.
- The `Chunks`, `BlockEntities`, `Entities`, `Placeholders`, `Overlays` hierarchy is kept; dynamic block entities continue to be batched globally by complete `MaterialKey`.
- Vertex tint, cutout, blend, double-sided and emission are written into the USDA material network; nearest-neighbor semantics are written to `minetomesh:samplerMode` and the material sidecar, and if Blender does not restore them automatically the Image Texture must be set to `Closest` manually.
- The `.usdapart` streaming temporary fragments are cleaned up after a successful, cancelled or failed export.
- This version immediately removes OBJ/MTL output and its implementation for the standard export, with no compatibility switch.

### Persistent locked selection

- The export GUI provides three independent toggles: `Preview` (hand preview), `Lock` (lock selection) and `Players` (export players).
- A locked selection does not require continuously holding the wand; identical hand and lock snapshots are deduplicated per frame, and different snapshots can be shown at the same time.
- Each singleplayer save or multiplayer server stores one lock record; switching dimension only hides it, and it is restored after returning to the original dimension.
- The configuration is written to `.minecraft/config/minetomesh/locked-selections.json`, using a SHA-256 profile key to hide the original path and server address.
- The configuration is replaced atomically through a temporary file in the same directory; corrupted JSON is quarantined as `locked-selections.json.corrupt-*`.
- The lock state lives entirely on the client and does not modify the wand component, the command protocol or server network payloads.

## Output layout

```text
minetomesh-exports/<name>/
├─ <name>.gltf
├─ <name>.bin
├─ <name>.usda
├─ report.json
├─ textures/
└─ materials/
```

## Installation

1. Install Minecraft 1.21.1 and NeoForge 21.1.244.
2. Remove any old MineToMesh JARs from the `mods/` folders of both client and server.
3. Install `MineToMesh-1.2.0.jar` on both client and server.

OBJ files generated by older versions are not modified or deleted; to get USDA, re-export with 1.2.0.
