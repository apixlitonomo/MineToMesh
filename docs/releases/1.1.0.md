# MineToMesh 1.1.0

MineToMesh 1.1.0 completes the dynamic render paths that the 1.0.0 coordinate handedness fix missed, and reduces the number of fragmented objects when mods such as Create produce many dynamic blocks in Blender.

## Changes

### Fixed mirrored dynamic models and flipped normals

- Removed the leftover `Z -> -Z` axis reflection from block-entity rendering, ordinary entity rendering and failure placeholder meshes.
- Removed the negative scale with determinant `-1` that MineToMesh injected into the `PoseStack` of block entities and ordinary entities.
- Dynamic models such as Create belts, cogwheels, shafts and mechanical arms are no longer mirrored along the Blender Y axis.
- Vertex positions, normals and triangle front faces of dynamic models once again follow the same right-handed coordinate contract.
- `extras.localPosition` of block entities and ordinary entities, entity placeholder bounding boxes and block placeholder bounding boxes now all keep the positive local Z.

The mapping after Blender imports the glTF is unchanged:

- Minecraft `+X` → Blender `+X`
- Minecraft `+Y` → Blender `+Z`
- Minecraft `+Z` → Blender `-Y`

### Dynamic block entities batched globally by material

- glTF and OBJ now both merge dynamic block-entity geometry by complete `MaterialKey`.
- Dynamic parts such as consecutive belts with the same material key become a single mesh object in Blender instead of being split per block position.
- The batching key includes texture, transparency mode, transparency threshold, double-sidedness, emission, blend semantics and sampler mode; merely similar texture names are never merged by mistake.
- glTF builds one global BlockEntities mesh/node per material key.
- OBJ uses per-material temporary fragment streams that are written as a single object when the export ends, and the temporary files are cleaned up after success, cancellation or failure.
- Static chunks, ordinary entities, placeholder meshes and grass side Overlay keep their original object boundaries.

### Metadata

- The NeoForge author field is updated to `岚苍穹 nebysse` (Lan Cangqiong nebysse).
- The 512×491 official mod cover and `logoBlur=true` are kept.

## Coordinate compatibility notes

Files that were already exported are not modified automatically. If Create dynamic models show a Blender Y-axis mirror, belt normals pointing inward or excessive object splitting, re-export the selection with 1.1.0.

This release does not change the Mod ID, Java package name, commands, network protocol, Export Wand data structure, export directory, or the one-block-per-meter scale.

## Installation

1. Install Minecraft 1.21.1 and NeoForge 21.1.244.
2. Remove any old MineToMesh JARs from the `mods/` folders of both client and server.
3. Install `MineToMesh-1.1.0.jar` on both client and server.

Export results continue to be written on the client of the player who started the action: `.minecraft/minetomesh-exports/`.
