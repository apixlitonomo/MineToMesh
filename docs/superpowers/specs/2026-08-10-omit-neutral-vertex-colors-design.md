# MineToMesh Neutral Vertex Color Omission Design

## Background

MineToMesh currently writes `COLOR_0` unconditionally for every glTF primitive. Even when all vertex colors are pure opaque white `RGBA(255,255,255,255)`, the Blender glTF importer still follows glTF semantics and generates `Mix Vertex Color` and `Mix Vertex Alpha` nodes, so the texture alpha goes through an identity multiplication before reaching the Principled BSDF.

## Goal

Omit `COLOR_0` for neutral vertex colors that make no visual contribution, so that the texture alpha of ordinary entity materials connects directly to the Principled BSDF Alpha in Blender, while keeping all real RGB tinting and vertex transparency.

## Decision

Decide per primitive:

- When every vertex is `RGBA(255,255,255,255)`, no color bufferView, accessor or `attributes.COLOR_0` is written to the glTF.
- When the R, G, B or A of any vertex is not 255, the existing normalized `VEC4 COLOR_0` is written in full.
- The decision uses the exact 8-bit `ColorRgba` after capture and introduces no threshold.
- OBJ output is unchanged; OBJ/MTL does not currently consume vertex colors.

## Data flow

`StreamingGltfSession` checks whether all vertex colors are neutral when writing a primitive, and turns the color binary segment into an optional value. `GltfDocumentBuilder` creates the color accessor and adds the `COLOR_0` attribute only when that segment exists. Positions, normals, UVs, indices, materials and topology are unaffected.

## Correctness boundaries

- Ordinary pets, animals and pure-white render streams omit `COLOR_0`.
- Grass, leaves, water, biome tinting, colored entity parts and any alpha other than 255 keep `COLOR_0`.
- As soon as one non-neutral vertex exists in a primitive, the whole color set is kept, avoiding splitting the primitive or changing the vertex correspondence.
- No attempt is made to change the nodes generated by the Blender importer, and no Blender post-processing script is added.

## Tests

1. The glTF JSON of a pure-white primitive contains no `COLOR_0`, and accessors/bufferViews contain no useless color segment.
2. A normalized `VEC4 COLOR_0` is still present when any RGB channel is not white.
3. A normalized `VEC4 COLOR_0` is still present when any alpha is not 255.
4. All existing glTF, OBJ, output transaction and full build tests pass.

## Acceptance criteria

After the glTF exported from an entity with pure-white vertex colors is imported into Blender, `Mix Vertex Alpha` is no longer triggered by `COLOR_0`; materials with real vertex tinting keep their original look and glTF semantics.
