# NeoForge 21.1.244 Compatibility Design

## Goal

Lower the minimum compatible Minecraft 1.21.1 NeoForge version of MC glTF Exporter from `21.1.248` to `21.1.244`, and use `21.1.244` as the actual compile and automated-verification baseline rather than merely relaxing the mod metadata.

Compatibility statement: Minecraft 1.21.1 with NeoForge `21.1.244` and later compatible `21.1.x` versions are supported.

## Scope of changes

1. Change `neo_version` in `gradle.properties` to `21.1.244`. ModDevGradle resolves 244 from it and compiles the production code, test code and development test mod.
2. The production mod's `neoforge.mods.toml` keeps generating the minimum version range through `${neo_version}`, so it automatically becomes `[21.1.244,)`.
3. Change the NeoForge dependency range of the development test mod to `[21.1.244,)` as well, so the test fixture does not artificially raise the runtime requirement.
4. Update the version descriptions in the README, the original specification and the implementation plan so the documentation no longer claims 248 as the minimum.
5. Change the NeoForge version in the glTF root extras from a hard-coded value to one read from the current runtime mod list. Exports record the real running version and never produce wrong metadata when run on 244, 248 or newer.

## Unchanged

- The Minecraft version stays `1.21.1`.
- Java, Gradle, ModDevGradle, the mod version and the glTF output contract are unchanged.
- No two separate source branches are maintained and no version-conditional reflection is added; the source must compile directly against the 244 API.
- The production JAR must still not contain the `mcgltf_test` development fixture.

## Verification

1. Run `./gradlew.bat clean test build` and confirm that all production code, unit tests and the development test mod compile successfully against NeoForge 21.1.244.
2. Inspect `build/libs/mcgltf-0.1.0.jar` and confirm that the production JAR does not contain `mcgltf_test`.
3. Inspect the generated `META-INF/neoforge.mods.toml` and confirm that the minimum NeoForge range is `[21.1.244,)`.
4. Run `./gradlew.bat runClient` to start the development client and confirm that the mod and the test fixture initialize and load resources in the 244 environment without fatal errors.
5. Keep the existing export and lifecycle tests so that lowering the compatibility baseline does not change functional behavior.

## Failure handling

If the code cannot compile on 244, first locate the APIs that changed between 244 and 248, and switch to calls that already exist in 244 and stay compatible in later 21.1.x versions. Do not fall back to the fake-compatibility approach of "compile against 248 and only relax the metadata".
