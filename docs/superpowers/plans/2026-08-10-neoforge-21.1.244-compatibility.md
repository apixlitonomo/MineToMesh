# NeoForge 21.1.244 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lower the minimum Minecraft 1.21.1 NeoForge compile and runtime baseline from 21.1.248 to 21.1.244, and verify that the complete export project builds and starts on 244.

**Architecture:** Use the single `neo_version` in `gradle.properties` to drive the ModDevGradle compile dependency and the production metadata, and keep the development test mod on the same minimum version. The export root extras read the actual NeoForge version from the current FML mod list, and the documentation consistently describes it as 21.1.244 and later compatible 21.1.x versions.

**Tech Stack:** Java 21, NeoForge 21.1.244, ModDevGradle 2.0.143, Gradle 9.2.1, JUnit 5.11.4.

- [ ] **Step 1: Replace the hard-coded root-extra version**

In `DefaultExportPipeline.rootExtras`, replace:

```java
extras.put("neoForgeVersion", "21.1.248");
```

with:

```java
extras.put("neoForgeVersion", loadedModVersion("neoforge"));
```

Add the focused helper:

```java
private static String loadedModVersion(String modId) {
    return ModList.get().getMods().stream()
            .filter(info -> info.getModId().equals(modId))
            .map(info -> info.getVersion().toString())
            .findFirst()
            .orElse("unknown");
}
```

This records the real version used by the client instead of claiming 248 under a 244 runtime.
