# Distant Horizons LOD Fallback Integration

MineToMesh optionally integrates with [Distant Horizons](https://gitlab.com/distant-horizons-team/distant-horizons) (mod id `distanthorizons`) to fill unloaded chunks within an export selection from Distant Horizons Level of Detail (LOD) terrain data instead of skipping them.

Like Sable compatibility, this integration is fully optional with no hard runtime dependency: MineToMesh loads and runs identically whether Distant Horizons is present or absent.

## Overview and Behavior

1. **Vanilla loaded chunks remain authoritative**: Any chunk loaded on the client (`ClientLevel.hasChunk == true`) is exported with full vanilla block models, fluids, block entities, and entities.
2. **Unloaded chunks fallback to LODs**: Any chunk in the selection that is not loaded on the client is queried against the Distant Horizons terrain data API (`IDhApiTerrainDataRepo.getAllTerrainDataAtChunkPos` / column query).
3. **Approximation**: Vertical data point runs are converted into axis-aligned quad/box meshes with outward-facing normals and `[0, 1]` UVs. LOD meshes do not capture block entities, entities, fluids, or complex custom BakedModels.
4. **Scene Hierarchy**: In glTF and USDA scenes, LOD geometry appears under a dedicated hierarchy node:
   - glTF: `DistantHorizons` -> `LodChunks` -> `c_<x>_<z>`
   - USDA: `def Xform "DistantHorizons"` -> `def Xform "LodChunks"` -> `def Xform "c_<x>_<z>"`
5. **No Force-Loading**: Vanilla chunks are never force-loaded into memory.
6. **Diagnostics in `report.json`**:
   - `distantHorizons.present`: boolean
   - `distantHorizons.apiVersion`: version string of DH API
   - `distantHorizons.lodChunksAttempted`: number of missing chunk positions queried
   - `distantHorizons.lodChunksFilled`: number of chunks successfully meshed from LOD data
   - `distantHorizons.lodChunksFailed`: number of chunks where DH returned no LOD data
   - `distantHorizons.note`: `"LOD geometry is approximate and generated from Distant Horizons terrain data"`

## Setup and Prerequisites

1. Install **Distant Horizons** client-side (and optionally server-side if playing multiplayer with distant generation).
2. Explore or generate LODs in advance: Distant Horizons only stores LOD data for areas that have been explored or generated by DH. If an unloaded chunk has never been visited or generated by DH, no LOD data exists and the chunk remains missing.
3. Export using the Export Wand or `/minetomesh export <name>`.

## Configuration

Distant Horizons fallback defaults to enabled whenever Distant Horizons is present at runtime.
It can be disabled via the JVM system property:
```text
-Dminetomesh.dh.fallback=false
```

## Limitations

- **Approximate Geometry**: Vertical columns are converted to axis-aligned boxes. Micro-details, complex geometry, non-cubic blocks (stairs, slabs, fences), and dynamic renderers are not represented in LOD fallback.
- **Fluids & Entities**: Distant Horizons LOD data does not include entity renderers or fluid animations.
- **Biomes & Tint**: Block colors and biome tints are approximate, resolved via DH API's `getBlockColorPreApi` or material color palettes.
- **Synchronous LOD Queries**: Currently terrain queries are executed synchronously before section iteration; large missing selections with lots of DH data will take time to decompress and mesh.
